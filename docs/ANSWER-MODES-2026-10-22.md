# 按题型展示答案、思路与代码

日期：2026-10-22。本轮开始时的代码已保存于 `eaac3f8`；用户进一步明确要求各分区独立切换，并按题型优先展示交付物。本轮替代之前只有章节滚动定位的阅读方式。

## 已实现的规则

| 题型 | 默认分区 | 其他内容 |
| --- | --- | --- |
| 单选、多选、判断 | 答案 | 思路、选项解析、全文 |
| 编写、修复、补全代码 | 代码 | 思路、复杂度/解析、全文 |
| 思路、提示、证明、开放讨论 | 思路 | 所需的结论、解析、全文 |
| 申论、公文、作文、论述成稿 | 参考作答 | 写作思路、材料分析、全文 |
| 计算 | 答案 | 思路、推导/解析、全文 |
| 概念解释及其他 | 存在时优先答案 | 实际生成的其他分区、全文 |
| 混合题型或无法分区的旧回答 | 全文 | 可识别的分区仍可手动查看 |

标签只展示实际生成的分区；生成过程中允许目标分区暂时等待内容，结束/中断后不保留空标签。模型输出的代码块内标题不会被当成新分区。多题归并时保留题号上下文；未识别的小节仍保留于补充与全文。章节下拉定位在当前分区内工作，全文保留原来的完整顺序。

每个分区保留独立滚动位置，手动选择后不会被后到的流式内容切走。新题清除旧分区状态，回答仍使用固定正文视口和原有翻页步长。图片自动收起、背景不透明度、窗口布局保持可用。

## 实现方式

提示词先根据题面交付物输出受控的 Markdown 类型注释，再按二级标题组织分区，最重要的交付物先生成。前端只消费这些明确标记与标题，不通过截图序号猜题型，也不额外创建一个分类模型请求。类型注释不显示在当前题解或历史 Markdown 中。

没有类型标记的旧回答根据明确小节保守回退；无法识别时直接显示全文。提示模式覆盖默认交付规则，只生成提示与关键观察，不因默认代码/答案分区而泄露完整答案。用户具体题目优先于复习专业与编程语言偏好。申论提示词要求交付符合材料、体裁和字数要求的正文，不能只给提纲代替成稿。
