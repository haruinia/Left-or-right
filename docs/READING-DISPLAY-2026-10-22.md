# 回答后的阅读空间与显示设置

日期：2026-10-22。继续处理用户提出的题图占空间、思路/答案定位、透明度、窗口长宽切换问题。此轮是在现有阅读修复上的产品优化，不把新增行为描述为 Gank 运行证据。

## 交互变化

- 待处理题图仍直接显示；第一段回答出现时自动收起，底部仅留“查看题图（N）”。点击可展开、放大，新增截图自动展开。图片仍保留在当前请求队列中，收起不删除数据，中断后仍可重新处理。
- 展开的图片改成单排横向滚动，最多占约 92px，不再因多图不断加行。8 张图回放时，正文从展开的 554px 恢复为收起的 646px。
- “定位章节…”根据实际 Markdown 标题生成，支持跳到思路、代码、最终答案等实际存在的章节。无章节的回答不显示该入口；它滚动完整正文，不隐藏、重排或编造答案内容。
- 底部“显示”提供背景不透明度（30%–100%）和当前百分比。只改变背景，文字保持不透明；原有 `⌘[` / `⌘]` 也走同一状态，并同步百分比。此语义是左右的阅读优化。
- 窗口提供窄长 560×760、标准 780×760、宽屏 1000×680；受当前显示器工作区限制。流式回答期间不自动改变窗口尺寸，避免阅读跳动。
- 收起至 320×240 后，展开恢复收起前的实际尺寸，包括手动调整过的尺寸。窗口位置、阅读尺寸、布局和背景不透明度会保存并在重启后恢复。
- 修复安装版偏好写入 `app.asar` 内只读目录的问题，改用 Electron 用户数据目录；仍兼容读取原有配置，保留环境变量覆盖。显示面板浮在正文上，不再挤占正文高度。

## 验证

1. Node 15 项通过，含背景/文字透明度分离、收起恢复尺寸、小显示器边界、偏好合并与写入目录。
2. API 106 项通过，有一条既有 Starlette/httpx 弃用提示；未修改后端业务逻辑。
3. 原阅读回归通过：返回从头显示、85% 翻页、第二题独占视口、流式追加保留位置。
4. 新浏览器回归通过：8 张题图自动收起/展开/放大、真实章节定位、背景 50% 而文字 opacity=1、新截图自动展开、下一题再收起，以及 560×760、1000×680、320×500 无整页横向溢出。
5. 安装版通过真实 preload/IPC 路径切换：标准 780×760 → 窄长 560×760 → 宽屏 1000×680 → 收起 320×240 → 恢复 1000×680。原生 AX 实际点击题图按钮和收起/展开按钮，状态正确。
6. 安装版重启后恢复背景 50%、窄长 560×760，随后把验收偏好恢复为标准 780×760、90%。受控题图/回答只存在于内存，未创建测试会话记录。
7. `npm run dist` 与 DMG 校验通过；源码/构建/安装的 102 个前端文件和构建/安装的 asar 哈希一致。临时调试端口与测试浏览器在完成后关闭。

可重复的用例：`tests/browser/reading-flow.js`、`tests/browser/reading-space.js`，通过 Playwright CLI 的 `run-code "$(cat 文件路径)"` 执行，先打开本地 9958 页面并保持 8001 API 可用。

本地证据位于忽略目录：`output/playwright/reading-space-flow.log`、`reading-space-native.log`、`reading-space-restart.log`、`reading-space-native-standard.png`、`reading-space-native-narrow.png`。这些回答使用受控 SSE，验证界面行为，不用于证明真实模型质量或速度。
